# 整理版与 PSI0-RAW：权重兼容及训练一致性复查

2026-11-03，范围为本机 RHSCI-Private（修改起点 `22723f2`）与本机 PSI0-RAW（HEAD `9ceb57802f1dd8c0326c5ffed170c17e1776025d`，同时包含其未提交的实际生产文件）。原树并非仅由该 Git HEAD 定义；数值清单记录读取文件的 SHA。原树活动代码、任务与检查点均未修改，未启动 GPU 训练、仿真或完整评测，没有推送远端。

**结论：对应结构的原版权重可以用于整理版推理，无需因目录整理重新训练；不能宣称全部历史结构无条件兼容，也不能保证两版完整训练得到相同参数或成功率。** 此前 CPU 自身回归只能证明整理版相关路径工作，本轮另外做了原/整理版配对、生产尺寸权重文件头及真实 ACT 权重推理核对。

## 本轮发现并修复的问题

| 问题 | 影响 | 修复及证据 |
| --- | --- | --- |
| Ψ0 专用方法的 VLM 学习率未同步 | 整理版 VGQ-VLM 的 VLM LoRA 原先继承 `1e-5`，原专用入口设 `1e-4`。AE 与 VLM 的相对更新比例会不同；不是可忽略的目录差异 | `training_config.resolve_training_plan` 对 VGQ-VLM、STATE-RECONSTRUCTION 同步语言/视觉/projector 三项 `1e-4`。冻结模式该项不产生 VLM 更新。新增配置回归；原真实 VGQ-VLM 保存配置也是 `1e-4` |
| 原四帧 STATE-RECONSTRUCTION 保存的原生名是 VGQ-AE | 按保存名直接建立整理版模型，会建立128维 ARDY 头，而真实权重是31维状态头 | `config.restore_checkpoint_method` 读取原 `controls.json` 的行为及方法；缺元数据时以31维头识别四帧重建。仍严格加载权重，不把早期单帧重建转换为四帧 |
| Ψ0 部署重新读取可变化的外部统计 | 保存配置已有训练时 bounds，原初始化仍可能用同路径的新文件覆盖，旧模型动作尺度随之改变 | `load_run_config` 传递恢复上下文，`ActionStateTransform.model_post_init` 优先保留完整嵌入 bounds；缺失时仍可读取外部文件。回归把磁盘 max 改为100，恢复后的训练 max 仍为2；普通新训练仍按原逻辑读统计 |
| GR00T 原无 Reader 完整 token 版本没有被接入 | 真实旧权重的 `rsci_memory_mode=full-vlm` 会被忽略，建立额外 Reader；原先不能将其视为正确迁移 | 在现有 GR00T 配置/Query/构造器内恢复 `FullMemoryQuery`，保留旧键与基类后替换的初始化顺序。默认仍为 Reader。原/整理版无 Reader 三步更新和推理相同；HF 保存/恢复无缺失或多余键 |

这些修复只作用于整理版，不改变原版已训练权重。学习率修复影响后续新训练；方法恢复和归一化修复影响正确部署旧权重。

若此前已经用整理版的旧 `1e-5` VLM 学习率训练过 LoRA 权重，本次修代码不能把那些结果追溯变成 `1e-4` 配方的结果；应继续按其真实保存配置解释。本轮没有发现或宣称存在这样一组已完成训练。

这里的“兼容”指模型结构、加载格式和已验证的计算范围；不代表每个生产大模型已经跑过 GPU 或 SIMPLE 闭环。

| 原版结果 | 整理版使用条件与证据 |

| ACT STATE、NO-STATE、EGQ-AE | 三种微型模型配对通过。实际两桌/抱箱 EGQ-AE 40k完整权重，在 CPU 经两版处理器、完整模型和反归一化输出16×36动作逐位相同，最大绝对差0。真实权重测试使用固定的合成非均匀 RGB，不是任务成功率测试 |
| GR00T STATE、NO-STATE、VGQ-AE Reader、VGQ-AE full-vlm 无 Reader | 四种微型模型配对通过。读取六个已完成20k检查点的配置和 Query 文件头，确认 STATE/Reader/full-vlm 对应关系；这六份不是全模型严格加载或 GPU 数值验收 |

## 两版重新训练是否一致

不能无条件说一致，也不能用相同 seed 代替配方核对。

- **已验证的模型计算**：13组微型模型在相同初始化、同一 batch、同一 RNG 下，参数键/形状、可训练参数集合、三步损失/梯度、模型状态、Adam 状态、Torch RNG 和固定 RNG 推理逐位一致；同 seed 构造的权重也一致。Ψ0 的推理项是固定噪声/时刻的速度场，另外几个骨干运行各自采样/预测函数。
- **尚未验证的完整训练**：生产 VLM、GPU BF16/TF32、完整 DataLoader、真实训练优化器/调度器、多卡归约和40k/115epoch长程没有跑原/整理版配对。微型对照使用统一 CPU AdamW 验证模型更新，不能替代生产优化器检查。
- **启动默认值不等于历史生产命令**：例如 Ψ0 每卡16，但默认只有可见/指定的卡数；单卡不是历史八卡 global128。VGQ-VLM 必须选 LoRA。EgoVLA 泛用默认40k步，115epoch需要相应显式参数/预设；真实已有某组是每卡64、累计1，不能因为有115epoch预设就套用16×4并声称逐位相同。GR00T 的默认初始化也不等于 SIMPLE 指定的50k初始化。需要逐项匹配实际产物的配置，不能只比较模型名字。
- **恢复路径有意修复过**：整理版 sampler epoch、累计尾更新及 worker 主 RNG 隔离修复意味着，若原版恢复触发旧错误，两版续训轨迹本就会不同。worker 内部随机增强状态和生产八卡精确恢复没有通用逐位保证。
- **执行配置要匹配**：历史 π0.5 `reference` 与 `both`、Ψ0 logits/重算设置，以及依赖版本和注意力后端都应记录。某些执行优化保留数学表达但有 BF16 舍入差异；不要承诺相同训练成功率或同一权重 SHA。

## 仍存在的限制与问题

1. π0.5 推理仍依赖完整训练数据身份：`openpi.rhsci.serve.Server` 校验整个数据集 fingerprint，`Processor` 从 `meta/stats.json` 读取统计。当前机器有配套数据时可使用；只有旧权重、没有原数据时不是真正独立的推理包。后续可以在现框架保存独立处理器统计并兼容旧格式，本轮未另改 π0.5 资产格式和归一化配方。
2. π0.5 原 v2 对接近相等分位数的维度置零，会丢掉稀少变化。这是此前已复现的共有问题，用户曾明确只修恢复；本轮继续保留，不能靠新版推理逆变换恢复训练时已丢掉的信息，也不因此要求原全部模型重训。
3. 原 GR00T full-vlm 权重现可按保存配置恢复，但常规新训练 CLI 仍默认 Reader，没有独立无 Reader 训练选择。不要把历史权重兼容误说成两种配方的 CLI 已完全统一。
4. λ₀ 以及生产尺寸 EgoVLA、Ψ0/π0.5/GR00T 的完整推理没有完成同输入配对；CPU/文件头证据不能替代该项。
5. SIMPLE 代码、评测包、指令、初态、控制频率、动作执行 horizon、随机种子和成功判定必须一起固定。同一权重换了评测资产也可能得到不同成功率；此轮没有重新判断官方线上是否新增更新，沿用[当前固定发布审查](SIMPLE_UPDATES_20261103.md)。

  --source-root /absolute/path/to/PSI0-RAW --backbone psi0 --report /tmp/paired-psi0.json
